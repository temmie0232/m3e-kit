# 04. 字

## type scale

`--t-<役割>` と `--lh-<役割>` を**必ず組で**使う。片方だけ変えると行間が崩れる。

| 役割 | px | 太さ | 使う場所 |
|---|---|---|---|
| display-l / m / s | 57 / 45 / 36 | 500 | 主役の数字。**1画面に1つ** |
| headline-l / m / s | 32 / 28 / 24 | 500 | 画面の見出し、ダイアログの表題 |
| title-l | 22 | 500 | トップアプリバーのタイトル、シートの表題 |
| title-m | 16 | 500 | 画面内の小見出し、幅いっぱいのボタンの札 |
| title-s | 14 | 500 | **セクション見出し**（`.label`、on-surface-variant） |
| body-l | 16 | 400 | 行の主文・本文 |
| body-m | 14 | 400 | 補助文・行の副題（on-surface-variant） |
| body-s | 12 | 400 | 注記 |
| label-l | 14 | 500 | ボタン・チップの札 |
| label-m | 12 | 500 | タブの札、バッジ |
| label-s | 11 | 500 | 最小の札 |

太さは **400 / 500 / 700 の3つだけ**（`--w-regular` / `--w-medium` / `--w-emph`）。
Expressive の「強調」は、寸法を変えずに太さを上げて作る。

**★合成ボールドを止める★** `font-synthesis-weight: none`（`base.css` に入っている）。
和文は端末により Regular/Medium/Bold しか持たないので、無い太さを要求すると
端末が合成して潰れる。

## 書体

同梱しない。Android では Roboto、iOS では SF、和文は端末の Noto Sans CJK /
Hiragino に落ちる。フォントの数百 KB は、遅い回線では実測で効く。

数字とコードだけ等幅を指名する（`--font-num`）。**桁揃えは装飾ではなく機能**なので
ここは譲らない。金額・件数・時刻を出すところには `font-variant-numeric: tabular-nums`
を付ける（`.mono` / `.num` クラスに入っている）。等幅を確実に効かせたいときだけ
`@fontsource/ibm-plex-mono` などを同梱する。

## ★和文の罠（ここが一番踏む）★

### 1. 負の字間を入れない

```css
letter-spacing: -0.02em;   /* ❌ */
font-feature-settings: 'palt';  /* ❌ 上と併用すると特に危険 */
```

負の `letter-spacing` は中黒・句読点の送り幅をほぼ 0 にする。隣の字に食われて
**消える**。実測で「写真・動画」が「写真動画」に見えた。
締まりが欲しいときは `font-weight` だけで作る。

`text-transform: uppercase` も入れない。日本語には効かず、混在した欧文だけが
浮き、字間だけが間延びする。

### 2. 和文の「最小幅」は1文字

欧文と違い、**和文はどこでも折り返せる**。つまり

- `grid-template-columns: 1fr`（= `minmax(auto, 1fr)`）
- flex の `min-width: auto`

は、日本語ラベルに対しては**何の保険にもならない**。区画が痩せた瞬間に
「すべ／て」と2行に折れ、行の高さが決まっている部品（接続ボタン群・
ナビゲーションバー・ボタン）はそこで崩れる。

**規約:**

```css
/* 札（ボタン・チップ・タブ・区画）は必ず */
white-space: nowrap;
/* 入りきらないときは行を増やさず末尾を省く */
overflow: hidden;
text-overflow: ellipsis;
min-width: 0;
```

grid の列は `minmax(0, 1fr)` にする（素の `1fr` は縮まない）。

折り返してよいのは**本文**と、**縮む相手が居ないもの**（幅いっぱいのボタン）だけ。

### 3. 端末幅 360px で確認する

日本語の UI で崩れるのはほぼ 360px 幅。実機が無いなら紙の上で数える:

```
360 − 左右 padding 16×2 = 328
「すべて」「写真」「動画」の3区画 → 1区画 109px
label-l 14px の和文3文字 ＝ 42px + padding 8×2 = 58px  → 収まる
6区画にすると 1区画 54px → 「メディア」（4文字 56px）が入らない → 折れる
```

## どこに何を使うか

| 場面 | 役割 |
|---|---|
| トップアプリバーのタイトル・シートの表題 | title-l（22）/ 500 |
| 主役の数字（月合計など、1画面に1つ） | display-m（45）/ 500 / tabular-nums |
| セクション見出し | title-s（14）/ 500 / on-surface-variant |
| 行の主文・本文 | body-l（16） |
| 補助文・行の副題 | body-m（14）/ on-surface-variant |
| ボタン・チップ | label-l（14）/ 500 |
| タブ・バッジ | label-m（12）/ 500 |

---

## 入力欄は 16px を下回らせない

```css
font-size: var(--t-input);  /* = 16px 固定 */
```

16px を下回った瞬間、iOS が入力欄のフォーカスで**画面を拡大して戻さなくなる**。
値ではなく名前で契約を表現するために専用トークンにしてある。
`--t-body-m`（14）を入力欄に使わない。

---

## OS の文字サイズに追従する

type scale は `rem` で書いてある（`--t-body-l: 1rem`）。`px` に書き換えない。
最大サイズにしても崩れないことを確認する — 崩れるとしたら、たいてい
「高さを固定した箱に文字を入れている」ところ。
