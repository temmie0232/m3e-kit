# 11. 状態の設計

**どの画面にも、必ず4つの状態がある。** 中身がある状態しか作っていない画面は
未完成。設計の時点で4つ全部を決める。

| 状態 | 仕様 |
|---|---|
| 読み込み中 | **骨**（`.skel`、surface-highest のパルス）。200ms 未満で終わるなら出さない |
| 空 | 「まだ何もありません」＋ **次にやる操作のボタン1つ**（`.empty`）。空画面は招待状 |
| エラー | 何が起きたか＋どうすれば直るかを1文（`.notice--alert`）。**再試行ボタン必須** |
| 中身あり | 本体 |

加えて、通信するアプリなら:

| 状態 | 仕様 |
|---|---|
| オフライン | 上部の札（`.banner`、error-container）。復帰したら消える |
| 部分読み込み | 低解像度 → 原寸をクロスフェード |
| 楽観的更新 | 送信・削除・並べ替えはサーバの返事を待たず先に画面を更新 |

---

## 読み込み中 — 骨（スケルトン）

**出てくるものと同じ形・同じ位置**の面を先に置いておき、中身が届いたら差し替える。
位置が動くと「読み込みが終わった」ではなく「画面が作り直された」に見える。

```html
<div class="panel">
  <div class="panel__body skel-group">
    <div class="skel" style="width: 60%; height: 14px"></div>
    <div class="skel" style="width: 90%; height: 14px"></div>
  </div>
</div>
```

- 走査グラデーション（シマー）は使わない。息をするだけのパルス
- **★200ms 未満で終わるなら出さない★** 一瞬だけ骨が出て消えるのは、
  何も出ないより遅く感じる

```ts
/** active になってから ms 経って初めて true を返す */
function useDelayed(active: boolean, ms = 200): boolean
```

- 全画面スピナーは禁止。**部分的に**骨を出す
- ボタンの中の処理中だけは印を出す（`.btn__busy`。文字は消さず右に足す）

---

## 空 — 招待状として書く

```html
<div class="empty">
  <span class="empty__title">まだ何もありません</span>
  <span>最初のひとつを追加すると、ここに並びます</span>
  <button class="btn btn--filled">追加する</button>
</div>
```

- お詫びを書かない（「データがありません」「該当なし」で終わらせない）
- **次にやる操作のボタンを必ず1つ**置く
- 絞り込みの結果が空のときは、ボタンは「絞り込みを外す」

---

## エラー — 1文で「何が」と「どうすれば」

```html
<div class="notice notice--alert">
  <strong>保存できませんでした</strong>
  <span class="muted">通信が切れています。つながってからもう一度試してください</span>
  <button class="btn btn--sm">もう一度試す</button>
</div>
```

- ❌「エラーが発生しました」…… 何も伝えていない
- ❌ エラーコードだけ …… 人が読むものではない
- ✅ 起きたこと + 次にできること + 再試行ボタン

一時的な失敗（送信できなかった）はスナックバー、
画面が成立しない失敗（一覧が取れなかった）は `.notice--alert` を本文の位置に。

---

## 楽観的更新

送信・削除・並べ替えは**サーバの返事を待たずに画面を更新**する。
失敗したら**静かに巻き戻して**スナックバーで知らせる。

```
押す → 画面から消す → スナックバー「削除しました / 元に戻す」
                   → 裏で API を叩く
                   → 失敗したら戻す + スナックバー「削除できませんでした」
```

これで**確認ダイアログが要らなくなる**。「本当に削除しますか」を出さずに済むのは、
取り消せるから。

- ダイアログを出すのは **本当に元に戻せないもの**（完全削除・課金・不可逆な設定）だけ
- スナックバーは 4〜6 秒。その間はサーバに投げないでおくのが最も安全

---

## 状態の切替でチラつかせない

- 骨 → 中身は**同じ位置・同じ高さ**にする
- 空 → 中身も同じ。空のときに高さが 0 になると、中身が来た瞬間に画面が跳ねる
- ダークとライトの切替でチラつかない（色は生成物からのみ取る）

---

## 部分読み込み（画像）

低解像度のサムネイルを先に出し、原寸が届いたらクロスフェード。
「読み込み中」の灰色の四角を見せない。

一覧は仮想化する。サムネと原寸は必ず分ける。
